# EDL (Equipment description language)

Альфа версия (прототип) декларативного шаблонизатора для описания оборудования и генерации 
данных в формат целевой платформы. Альфа версия языка создана русскоязычной (хотелось понимать, насколько это будет 
ужасно и это ужасно), последующие версии будут использовать латиницу (и английский).

Для начала можно создать переменную:
```ignorelang
$Переменная: str = "строка";
```

И написать комментарий:
```ignorelang
/ это же переменная! /
$Переменная: str = "строка";
```

Все описание объявления переменных, директив, параметров и объектов завершается символом точки с запятой (`;`)  

Язык поддерживает базовые (всем привычные) типы данных:
```ignorelang
$Переменная_1: str = "строка";
$Переменная_2: int = 10;
$Переменная_3: float = 10.0;
$Переменная_4: bool = Да;
```

Язык поддерживает массивы:
```ignorelang
$arr_1: arr[int] = [10];                                                    / с одним элементом  /
$arr_2: arr[int:3, str:2] = [1, 2, 3, "4", "5"];                            / с тремя int и двумя str  /
$arr_3: arr[int:2, arr[int:4]..] = [1, 2, [0, 1, 2, 3], [4, 5, 6, 7]]       / из двух int и множества массивов с 4 int  /
$arr_4: arr[arr[int..]..] = [[0], [1, 2, 3], [4, 5]];                       / неопределенное количество массивов с неопределенным количеством int /
```
* `..` - эллипсис, возможен только как **заключительный** символ при описании массива. (Сообщает что количество может быть любым)

В основном такой синтаксис массива нужен для проверки входных данных, так как язык не позволяет их визуализировать,
но генерирует ошибку типа, если тип не соответствует заявленному. Массив поддерживает вложенность на 10 уровней, далее 
генерируется исключение.

Создан также не совсем обычный тип - диапазон:
```ignorelang
/ символ ~ обозначает бесконечность /
$inf_range: float = диапазон[~, ~];             / бесконечный диапазон /
$int_range: int = диапазон[0, 10];              / целочисленный диапазон /
```

Переменная может принимать любое значение в границах диапазона.

Язык содержит несколько основных сущностей:
* **шаблоны** - области видимости для группировки логически связанных объектов, например нескольких взаимосвязанных  
единиц оборудования. Шаблон позволяет создавать внутри себя `контекст` (множество), нигде более это невозможно.
* **контексты** - области видимости для группы логически связанных переменных. С помощью контекстов можно создавать  
множество объектов по образцу. Можно думать про контекст как про массив массивов данных, 
необходимых для создания множества одинаковых объектов. Данные загружаются из файла директивой `#загрузить`,
далее итеративно распаковываются в переменные контекста (согласно описанию массива). Из переменных контекста итеративно создаются
необходимые объекты.
* объекты - сущности описывающие оборудование. К ним относятся: `сигнал`, `соединение`, `оборудование`.

Пример:
```ignorelang
/ после директив препроцессора точка с запятой не нужна /
#загрузить "path/file.json" пример_данных

шаблон Пример_шаблона {
    
    контекст Пример_контекста {
        $equip_number: int;
        $host: str;
    };
    
    / описываем переменные и массив данных для распаковки /
    / данные из file.json будут итеративно загружаться в переменные контекста /
    $для_контекста: arr[arr[int, str]..] = пример_данных;
    
    / директива .подстановка как раз и распаковывает данные в контекст /
    / (данные распаковываются какбы в два этапа /
    .подстановка в Пример_контекста из $для_контекста;
    
    / значения переменных можно использовать для динамической конфигурации имен объектов /
    оборудование класс_ц Пример_оборудования_ + $host {
    
        / это оборудование будет создаваться итеративно из переменных контекста /
        / для этого его нужно подключить к контексту директивой .использовать /
        / (более детальное описание этой директивы будет дано ниже) /
        .использовать Пример_контекста линейно значения все;
        
        / берем идентификатор из контекста /
        Идентификатор: int = $equip_number;
    };
};
```

## Описание работы (кратко)
Процесс трансляции представляет собой пять этапов:
1. Препроцессинг - возможность подстановки в код данных из внешних файлов и создание символов для их хранения  
2. Лексический анализ - токенизация лексем, проверка их корректности / допустимости
3. Синтаксический анализ - проверка корректности выражений
4. Семантический анализ - проверка допустимости выражений, разрешение символов, анализ типов.
5. Трансляция - трансляция EDL абстракций в целевой формат.
6. Постпроцессинг (отсутствует) - проверка корректности финальных данных с точки зрения целевой платформы (валидация).

## Порядок разрешения символов

### Общий
1. переменные
2. директивы
3. параметры
4. объекты

### Глобальный (уровень модуля)
1. переменные
2. директивы (они могут использовать значение переменной)
3. объекты -> (шаблон, оборудование, сигнал, соединение)

### Шаблон (уровень шаблона)

1. контекст
2. переменные
3. директивы
4. параметры
5. соединения (как отдельный объект, так как их могут использовать другие объекты)
5. объекты

Контекст рушит иерархическую структуру объекта, создавая из нее линейную. Можно создавать множество контекстов, 
один объект может использовать только один контекст.

## Объекты

### Оборудование
область видимости для описания оборудования.

Порядок разрешения символов:
1. переменные
2. директивы
3. параметры
4. соединения
5. блоки

### Соединение
Запрещено создание соединений из контекста и запрещено использование в них директивы 'использовать'  
На данный момент результат таких действий не определен.
(директив для соединения пока нет)

Порядок разрешения символов:
1. переменные
2. директивы
3. параметры

Для привязки соединения создан специальный объект - Link -> ConnectionLink.  
Объект хранит имя соединения, к которому осуществляется привязка, а также сам объект.  
Объект связанный соединением находит его по имени (lookup()) и получает его идентификатор.

### Сигнал

Сигнал - это область видимости (параметры) которыми можно описать абстрактный сигнал.

Порядок разрешения символов:
1. переменные
2. директивы
3. параметры
4. соединения

## Нереализованные пункты / ошибки / техдолг / особенности
1. Обработка типов диапазонов (типизация) - сейчас типы не проверяются на стадии ADT, игнорируются или не допускаются значения float и
    представление бесконечных значений (-inf -> inf);
2. Нет проверки типов массивов - есть генерация описания типа массива (например arr[str:6, arr[int:7]..]).  Отсутствует проверка типов в переданном массиве 
в качестве дынных;
3. Нет реализации правил (распаковка данных);
4. Нет реализации фильтров значений в директиве 'использовать';
5. Нет реализации правил (rule) подстановки данных в строки;
6. При нескольких адресах в соединении и указании обработчиков, последний указанный перезаписывает предыдущий (нет правил / ограничений на этот счет);
7. Нет возможности именовать форматы для значений и тревог (сейчас генерируются машинно). Поэтому на каждый объект сейчас генерируется один зависимый объект (кроме соединений);
8. Visitor реализован не в полном объеме - в некоторые ноды не заходим ни в AST ни в ADT (в том числе поэтому пока нет реализации проверки типов массива и диапазона)
9. Нет понимания, как лучше привязывать вложенные объекты к внешним (если не используется контекст)
10. Обработка конкретных операций в трансляторе DynamicScope в который функция верхнего уровня выставляет нужные значения а обработчики параметров их корректируют удаляют итд (не самая лучшая идея)
11. Не реализовано формирование формата сообщения о тревоге и формат сообщения из стандартных полей (формат пока большей частью хардкодный)
12. Внешние данные поддерживаются только в формате arr[arr[any..]..]. Количество элементов (и их типы) должны совпадать с количеством переменных контекста.

## Запуск

### Проверка результатов работы препроцессора
Флаг `-e` подволяет прервать выполнение после стадии препроцессинга и сохранить результаты препроцессинга в файл.  
Команда запустит препроцессор на выбранном файле и после завершения стадии препроцессинга сохранит результат в текущую директорию в файл `out.txt`
```bash
python edl.py -e -f example_with_ctx.edl
```  
Команда запустит препроцессор на выбранном файле и после завершения стадии препроцессинга сохранит результат в указанную директорию в файл `out.txt`
```bash
python edl.py -e -f example_with_ctx.edl --output-path=old_bcp
```

### Компиляция
Скомпилирует файл в целевые файлы в указанную директорию
```bash
python edl.py -f example_with_ctx.edl --output-path=old_bcp
```

### Конфигурация
```bash
mv edl.py edl
sudo chmod +x edl
sudo ln -s $(pwd)/edl /usr/local/bin/
```
