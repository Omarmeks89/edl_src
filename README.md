# EDL (Equipment description language)

Альфа версия (прототип) декларативного шаблонизатора для описания оборудования и генерации  
данных в формат целевой платформы. Альфа версия языка создана русскоязычной,  
последующие версии будут использовать латиницу (и английский).

## Структура проекта

```
edl/
+-- src/                                  # исходный код языка
|   +-- _ast.py                             # символы ast
|   +-- adt.py                              # финальное представление данных
|   +-- code_reader.py                      # класс загружающий исходный код
|   +-- exceptions.py                       # исключения
|   +-- parser.py                           # лексер и парсер языка edl
|   +-- preprocessor.py                     # препроцессор (токены, лексер и парсер препроцессора)
|   +-- stree.py                            # префиксное дерево для разрешения символов препроцессора
|   +-- tokens.py                           # токены языка edl
|   +-- tools.py                            # загрузка конфигурационного файла
|   +-- scope.py                            # области видимости runtime
|   +-- finalizer.py                        # разрешение AST, проверка типов
|   +-- symbols_graph.py                    # граф использования макросимволов и файлов данных
|   `-- translator.py                       # семантический разбор
|
+-- test/
|   `-- unit/
|       +-- preprocessor_test.py            # базовые тесты препроцессора
|       +-- grabber_test.py                 # тест adhoc парсера препроцессора для получения символов edl текста
|       +-- symbols_graph_test.py           # тест графа макро символов
|       `-- stree_test.py                   # тесты ппрефиксного дерева
|
+-- translators/                          # содержит трансляторы ADT в целевой формат (диалекты)
|
+-- README.md
+-- CHANGELOG.md                    
+-- edl                                   # точка входа
+-- setup.yml                             # конфигурационый файл (указание путей до файлов данных для проверки)
`-- req.txt                               # зависимости проекта
```

## Синтаксис

1. Все операции (кроме директив начинающихся с `#`) завершаются символом `;`
2. Все области видимости / блоки (т.е. текст, заключаемый в `{}`) завершаются символом `;`
3. Объявление переменной и разыменование начинается с символа `$`.

   Синтаксис:  
   ```$<var-name>: [type] = [value];```

   В объявлении контекста допускается декларация переменных:  
   ```$ctx_data_1, $ctx_data_2: int;```

   Эти переменные будут использованы контекстом как контейнеры для распаковки значений.  
   Присваивание значений одной переменной другой запрещено.

   Присвоить переменной значение можно только в момент объявления переменной (за исключением контекста)

   Получение значения переменной `prev_var` (и присваивание другой переменной):  
   ```$new_var: str = $prev_var;```
   Переменная может быть определена на любом уровне вложенности, от уровня вложенности будет зависеть ее область
   видимости.  
   Переменная обязана иметь уникальное имя - это сделано специально для исключения источников неопределенного поведения.
4. Комментарии

   Любая последовательность символов, заключенная между символами `/` является валидным комментарием.
   Комментарий может находиться как в одной строке, так и быть многострочным
   Пример:
    ```
    / Однострочный /
    / ------------ /
    / пример
      многострочного
      комментария /
    ```

## Типы данных

`edl` является типизированным языком и реализует проверку типов на стадии трансляции.  
Реализованные типы данных: `int`, `float`, `bool`, `str`, `arr`(array), `диапазон`

### Строки

Любая последовательность символов, заключенная в кавычки (`"` или `'`) является строкой.  
Пример:

```ignorelang
$Переменная: str = "строка";                                                / два варианта написания строк /
$Переменная_2: str = 'строка';
```

Внутри строки может существовать подстрока, заключенная в кавычки другого типа:

```
$test_str_var: str = "test str 'with nested prs'";
```  

### Целые числа

Любая последовательность цифр, число начинающееся с оператора `-` считается валидным типом `int`
Пример:

```ignorelang
$Целое: int = 10;
$Отрицательное: int = -10;
```

### Вещественные числа (числа с плавающей точкой)

Любые последовательности цифр, разделенных символом `.`, в том числе начинающиеся с оператора `-`  
считается валидным типом `float`
Пример:

```ignorelang
$Вещественное_положительное: float = 10.055;
$Вещественное_отрицательное: float = -10.055;
```

### Массивы

Описание массива начинается с ключевого слова `arr`, описание элементов массива  
помещается в квадратные скобки.

Сочетание типов в массиве может быть любым, массив в данном случае это просто
типизированная последовательность данных.

Возможно несколько вариантов описания типов элементов в массиве:

1. Указание типов согласно их количеству, без группировки

```ignorelang
$arr_1: arr[int] = [10];    
$arr_2: arr[int, str] = [10, "20"];  
$arr_3: arr[int, int, str, str] = [10, 20, "30", "40"];    
```

2. Указание типов с группировкой по количеству:

```ignorelang
$arr_3: arr[int:2, str:3] = [10, 20, "30", "40", "50"];    
```

3. Указание произвольного количества элементов. Символ эллипсис `..`(представляющий произвольное количество элементов)  
   должен быть **заключительным** символом при описании типа.  
   (При указании `..` количество элементов типа не указывается)  
   Правильно:

```ignorelang
$arr_4: arr[int:2, str..] = [10, 20, "30", "40", "50", "78"];               / ошибка /
$arr_5: arr[int..] = [1, 2, 3, 4, 5, 6, 7];                                 / ошибка /
$arr_6: arr[arr[int..]..] = [[1, 2, 3], [4, 5], [0]];                       / ошибка /
```

**Неправильно**:

```ignorelang
$arr_7: arr[int:2, str:4..] = [10, 20, "30", "40", "50", "78"];
$arr_8: arr[int.., int] = [10, "30"];
$arr_8: arr[arr[str].., int:2] = [["10"], 20, 30];
```

### Диапазоны

Диапазоны - специальный тип для указания границ значений. Типы значений должны соответствовать типу диапазона,  
не допускаются разные типы границ в диапазонах (нельзя сочетать `int` с `float`).  
**(иные типы недопустимы для диапазона)**

```ignorelang
/ символ ~ обозначает бесконечность /
$inf_range: float = диапазон[~, ~];                                         / бесконечный диапазон /
$float_range: float = диапазон[1.0, 11.0];                                  / интервал вещественных чисел /
$int_range: int = диапазон[0, 10];                                          / целочисленный диапазон /
$int_range_2: int = диапазон[-100, 10];
```

**Неправильно**

```ignorelang
$inf_range: float = диапазон[~, 10];                                        / ошибка /
$float_range: float = диапазон[Да, 11.0];                                   / ошибка /
$int_range: int = диапазон["-10", 10];                                      / ошибка /
```

Переменная может принимать любое значение в границах диапазона (реализация на стороне транслятора)

## Препроцессор

Препроцессор нужен для операции загрузки входных значений из файлов (реализовано), определения и использования
макро-символов для директив условной компиляции (в разработке).
Директивы препроцессора начинаются с символа `#`.

### Директива `upload`

Используется для загрузки необходимых файлов с данными, если используются
контексты. Поддерживаемый формат данных - это массив массивов (`[[1, 2, 3], [4, 5, 6]]`).

Синтаксис:

```ignorelang
# upload [параметр] [символ]
```

В качестве параметра директива `upload` ожидает строку с путем к файлу (относительно
той директории, из которой будет выполняться команда `./edl`).  
В имени символа допускаются только числа, символы UTF-8 обозначающие буквы, символы нижнего подчеркивания.  
Имя символа не может начинаться с числа.

```ignorelang
# upload "data/file.json" SYMBOL_NAME
```

## Директивы

Символы директив начинаются с символа `.`

### .подстановка

Директива-распаковщик, распаковывает данные из переменной в переменные контекста.  
Может использоваться только контекстом. В качестве источника данных может использовать только переменную.

Синтаксис:
```.подстановка в <имя_контекста> из [переменная];```

Пример:

```ignorelang
.подстановка в Данные из $var;
```

### .использовать

Директива привязки, необходима при генерации объектов из контекста.  
Используется в объектах оборудования и сигнала для подключения нужного контекста для создания объектов.

Синтаксис:
```.использовать <имя_контекста> [способ распаковки] значения [фильтр значений];```

#### Способы распаковки:

* **линейно** - итеративная распаковка линейной структуры данных (массива).  
  Это значит что за одну итерацию N переменных контекста будут распакованы в N параметров объекта.

#### Фильтр значений

* **все** - указывает на отсутствие какой-либо фильтрации значений

Пример:

```ignorelang
.использовать Данные_для_генерации_оборудования_ядра линейно значения все;
```

### .привязать

Директива привязки, необходима для указания источника данных для сигнала / оборудования

Синтаксис:
```.привязать <имя_соединения>;```

Пример:

```ignorelang
.привязать Соединение;
```

## Сущности

### Шаблон

* **шаблоны** - области видимости верхнего уровня, созданные для группировки логически связанных объектов, например
  нескольких взаимосвязанных  
  единиц оборудования и их данных. Шаблон позволяет создавать внутри себя `контекст(ы)` - множество логически связанных
  значений, для  
  создания описываемого оборудования по 'шаблону'. Имя шаблона должно быть уникальным.

Синтаксис шаблона: ```шаблон <имя_шаблона> { тело_шаблона };```  
Пустой шаблон:

```ignorelang
шаблон Пример_шаблона {};
```

Тело шаблона может содержать:

1. Переменные
2. Директивы
3. Контексты
4. Оборудование
5. Соединения

### Контекст

* **контексты** - области видимости для группы логически связанных переменных. С помощью контекстов можно создавать  
  множество объектов по образцу. Можно думать про контекст как про массив массивов данных,
  необходимых для создания множества одинаковых объектов. Данные загружаются из файла директивой `#upload`,
  далее итеративно распаковываются в переменные контекста (согласно описанию массива). Из переменных контекста
  итеративно создаются
  необходимые объекты.
* объекты - сущности описывающие оборудование. К ним относятся: `сигнал`, `соединение`, `оборудование`.

Контекст использует директиву `.подстановка` для присванивания значений в переменные контекста.
Если объект использует контекст, то имена переменных контекста (при совпадении) имеют приоритет перед обычными
переменными

Пример:

```ignorelang
#upload "path/file.json" пример_данных

шаблон Пример_шаблона {
    
    контекст Пример_контекста {
        $equip_number: int;
        $host: str;
    };
    
    / описываем переменные и массив данных для распаковки /
    / данные из file.json будут итеративно загружаться в переменные контекста /
    $для_контекста: arr[arr[int, str]..] = пример_данных;
    
    / директива .подстановка как раз и распаковывает данные в контекст /
    / (данные распаковываются какбы в два этапа /
    .подстановка в Пример_контекста из $для_контекста;
};
```

### Соединение

Соединение может быть создано как на самом верхнем уровне (на уровне шаблона), так и на вложенных уровнях.  
Главное, чтобы объект использующий соединение был определен ниже по уровню вложенности.  
Используется типом `сигнал` для определения источника данных о сигнале (его значении). Соединение должно иметь
уникальное имя.

Соединение представляет собой настройки сервера обработчика сигналов

Соединение содержит несколько полей:

* **Идентификатор** - значение, определяющее id обработчика;
* **Адрес** - значение, определяющее адрес обработчика;
* Параметр `обработчик` поля `Адрес` указывает имя обработчика,
* которое будет указано в конфигурации для идентификации обработчика сигнала

**Поля и параметры могут использовать переменные в качестве значений**

Запрещено создание соединений из контекста и запрещено использование в них директивы `.использовать`
На данный момент результат таких действий не определен.

Синтаксис:

```ignorelang
соединение <имя_соединения> {};
```

Пример:

```ignorelang
соединение Соединение {
        Идентификатор: str = "name";
        Адрес: str = $conn обработчик="handler";
    };
```

Пример с соединением:

```ignorelang
шаблон Пример_шаблона {

    соединение Соединение {
        Идентификатор: str = "name";
        Адрес: str = $conn обработчик="handler";
    };
    
    контекст Пример_контекста {
        $equip_number: int;
        $host: str;
    };
    $для_контекста: arr[arr[int, str]..] = пример_данных;
    .подстановка в Пример_контекста из $для_контекста;
};
```

### Оборудование

Объект представляющий описываемое оборудование.  
Оборудование может содержать объекты сигналов и другие объекты оборудования со своими сигналами итд.  
Оборудование должно иметь уникальное имя.

Тело оборудования может содержать:

1. Переменные
2. Директивы
3. Оборудование
4. Соединения
5. Сигналы

#### Поля

* **Идентификатор** - поле описывающее идентификатор оборудования (любой тип). В качестве значения может быть
  использовано  
  как значение-константа, так и переменная и переменная контекста. Описание оборудования начинается с ключевого
  слова `оборудование`

Синтаксис:
```оборудование [класс] <имя_оборудования> (расширения имени) { тело оборудования };```

#### допустимые классы

* **класс_ц** - цифровое оборудование (дискретные значения сигнала)
* **класс_а** - аналоговое оборудование (значения с плав. запятой)

#### расширение имени

Имя объекта можно расширить, добавив к нему дополнительные идентификаторы (в произвольном количестве). Пример:

```ignorelang
оборудование класс_ц Пример_оборудования_ + $host
```

Идентификаторы (независимо от их типа) будут интерпретироваться как строка

Результатом расширения будет имя:

```ignorelang
Пример оборудования 127.0.0.1
```

(Символы нижнего подчеркивания заменяются на пробельные символы)

```ignorelang
#upload "path/file.json" пример_данных

шаблон Пример_шаблона {

    соединение Соединение {
        Идентификатор: str = "name";
        Адрес: str = $conn обработчик="handler";
    };
    
    контекст Пример_контекста {
        $equip_number: int;
        $host: str;
    };
    $для_контекста: arr[arr[int, str]..] = пример_данных;
    .подстановка в Пример_контекста из $для_контекста;
    
    / значения переменных можно использовать для динамической конфигурации имен объектов /
    оборудование класс_ц Пример_оборудования_ + $host {
    
        / это оборудование будет создаваться итеративно из переменных контекста /
        / для этого его нужно подключить к контексту директивой .использовать /
        .использовать Пример_контекста линейно значения все;
        
        / берем идентификатор из контекста /
        Идентификатор: int = $equip_number;
    };
};
```

### Сигнал

Сигнал служит для описания сигнала оборудования.  
Не является самостоятельным блоком и должен быть определен внутри оборудования. Не может содержать вложенные сигналы.
Может содержать объект соединения. Сигнал должен иметь уникальное имя.

Синтаксис:  
```сигнал [direction] [type] <name> { signal-body };```

* **direction** - входной / выходной
* **type** - аналог (значения с плав. точной) / дискрет (дискретные значения)
* **name** - имя сигнала, поддерживает конкатенацию в нужными значениями переменных

Поля:

* **Оборудование** - идентификатор оборудования
* **Идентификатор** - идентификатор (номер) сигнала
* **Значение** - описание значения сигнала. Поле содержит дополнительные параметры для описания значение.  
  Синтаксис:
  ```Значение: [тип] = [константа или диапазон] статус=<статус> важность=<константа> отображать=<строка-сообщение>;```

  Параметры служат для создания `alias` для значения, определение категории тревоги и статуса сигнала (норма / авария)
    * **статус** - тревога / норма (в нижнем регистре)
    * **важность** - степень критичности тревоги, допустимый тип - int
    * **отображать** - должно содержать строку-сообщение, на которое будет заменено числовое значение. Если указать для
      бесконечного диапазона - будет ошибка.
    * **метка** - предусматривает использование строкового литерала
* **Формула** - поле, описывающее формулу сигнала и используемые формулой параметры  
  Пример:
  ```Формула: str = "@up{instance='%', job='%'} %" параметр=$Адрес_экспортера параметр=$server_job параметр=$zero_if_no_data;```
    * **%** - оператор подстановки значения. Вокруг строковых значений должны быть выставлены кавычки: `'%'`. Вложенные
      кавычки должны отличаться от внешних
    * **параметр** - может быть переменной, константой. Количество параметров должно совпадать с количеством операторов
      подстановки, порядок описания операторов должен соответствовать спецификации формулы и определяться слева направо.
* **Формат** - строка, описывающая конечное сообщение для пользователя.
* **Квитируемый** - Принимает логический тип (bool) - Да / Нет
* **Журналируемый** - Принимает логический тип (bool) - Да / Нет

Пример:


## Нереализованные пункты / ошибки / техдолг / особенности

1. Нет проверки типов массивов - есть генерация описания типа массива (например arr[str:6, arr[int:7]..]). Отсутствует
   проверка типов в переданном массиве
   в качестве данных;
2. Нет реализации правил (распаковка данных);
3. Нет реализации фильтров значений в директиве 'использовать';
4. Нет реализации правил (rule) подстановки данных в строки;
5. При нескольких адресах в соединении и указании обработчиков, последний указанный перезаписывает предыдущий (нет
   правил / ограничений на этот счет);
6. Обработка конкретных операций в трансляторе DynamicScope в который функция верхнего уровня выставляет нужные
   значения, а обработчики параметров их корректируют удаляют итд (не самая лучшая идея)
7. Внешние данные поддерживаются только в формате arr[arr[any..]..]. Количество элементов (и их типы) должны совпадать с
   количеством переменных контекста.
8. Расширение имени дополнительными токенами работает только для финального представления, но (пока) не помогает
   сделать имя изначально уникальным

## Возможные источники ошибок при трансляции

Ниже описаны несколько самых неприятных типов ошибок, при отлове которых трейсинг плохо помогает и с его помощью
будет трудно понять место начала ошибки:

1. Не закрытый комментарий - проверить, что комментарии закрыты
2. Использование внутри строки такого же типа кавычек, как и снаружи - изменить внутренний тип кавычек
3. Незакрытая кавычка при описании строки (или кавычка другого типа) - закрыть строку кавычкой того же типа
4. Неуникальное имя объекта (шаблона, контекста, оборудования итд) - следить, чтобы все имена были уникальными

## Запуск

Флаг `-f` необходим для указания файла исходного текста для трансляции

```bash
python edl.py -f example_with_ctx.edl
```

Флаг `-e` подволяет прервать выполнение после стадии препроцессинга и сохранить результаты препроцессинга в файл.  
Это позволяет проверить корректность подстановок препроцессора.
Команда запустит препроцессор на выбранном файле и после завершения стадии препроцессинга сохранит результат в текущую директорию в файл `out.txt`
```bash
python edl.py -e -f example_with_ctx.edl
```  
Команда запустит препроцессор на выбранном файле и после завершения стадии препроцессинга сохранит результат в указанную директорию в файл `out.txt`
```bash
python edl.py -e -f example_with_ctx.edl --output-path=old_bcp
```
